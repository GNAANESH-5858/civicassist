# Security and privacy

## Principles

- **No submission on the citizen's behalf.** The app never posts to government portals, sends email or calls any external service for the citizen. It only links to official channels from the source registry.
- **No accounts.** Nothing requires sign-up. Sender details for a letter (name, address, phone, email) stay in the browser and are never sent to AI or stored.
- **AI is optional and sees masked text only.** `maskPII` removes phone numbers, emails, Aadhaar-like and other ID numbers before any text reaches `/api/llm`. The function masks again server-side.
- **Facts never come from a model.** Authorities, channels, phone numbers, URLs and safety advice come from `src/data/civic/`. A polished letter is accepted only if every fact token survives and no new number appears (`src/lib/letter/polish.ts`).

## Saved records (`/api/records`)

- A record is created with a random UUID and a 256-bit random token. Only the SHA-256 hash of the token is stored. The citizen keeps the token in a capability link (`/my-complaints#r=id.token`); the fragment is never sent to the server in page requests.
- A wrong token and a missing record get the same 404, so record ids cannot be probed.
- Bodies are limited to 16 KB, validated with strict zod schemas (unknown fields rejected), and text is masked server-side.
- Statuses are self-reported by the citizen. `submitted_via_integration` cannot be set through the API because no integration exists.
- Admin access needs `CIVICASSIST_ADMIN_TOKEN` (at least 32 characters, compared in constant time). If it is unset, admin access is disabled. Admins cannot delete records, and every admin change is tagged `by: admin` in the history.

## Function hardening

- `/api/llm` accepts only `rewrite`, `answer`, `extract` and `polish`, limits input to 64 KB, wraps user text as data (`asData` strips wrapper tags) and validates `extract` output against a schema (502 if invalid).
- Rate limits: `/api/llm` 30/min, `/api/records` 60/min per IP (Netlify function config).

## Headers

`netlify.toml` sets `Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` and HSTS.

## Sample data

`public/data/triaged.json` and `data/complaints.csv` are synthetic and generated by `scripts/gen_complaints.ts`. The officer dashboard labels them as sample data. Never commit real citizen complaints.
